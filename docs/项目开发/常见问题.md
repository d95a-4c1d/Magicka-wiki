# 常见问题

## Unity Version Control 无法连接

### 症状

PlasticSCM 或 Unity Version Control 无法读取仓库、分支和许可证信息，并反复显示：

```text
An unexpected error has occurred on server.
For more information check the server log.
```

命令行执行 `cm status` 时，也可能把正常存在的私有仓库报告为“无法获取存储库”。

### 常见原因

如果网络可以访问 Unity DevOps，但 PlasticSCM 日志包含以下内容，通常是本地认证缓存仍保存着已经过期的 SSO/LDAP 令牌：

```text
LDAP 令牌已过期
Token Expired
GetSeid
```

macOS 上的日志一般位于：

```text
~/.plastic4/logs/plasticx.relevant.log.txt
~/.plastic4/logs/plasticx.debug.log.txt
```

只在 Unity Hub 中退出并重新登录不一定能解决问题。Unity Hub 可能已经取得新会话，但 PlasticSCM 仍会继续读取 `~/.plastic4/tokens.conf` 中的旧令牌。

### 修复方法

先保存 Unity 中尚未保存的场景和资源，然后完全退出 PlasticSCM。将认证缓存移动到带时间戳的备份目录：

```bash
backup="$HOME/.plastic4/cache-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup"

[ -f "$HOME/.plastic4/tokens.conf" ] && \
  mv "$HOME/.plastic4/tokens.conf" "$backup/tokens.conf"

[ -f "$HOME/.plastic4/cloudedition.token" ] && \
  mv "$HOME/.plastic4/cloudedition.token" "$backup/cloudedition.token"

[ -d "$HOME/.plastic4/events" ] && \
  mv "$HOME/.plastic4/events" "$backup/events"
```

重新启动 PlasticSCM，并按界面提示登录 Unity 账号。客户端应当生成新的 `~/.plastic4/tokens.conf`。

随后在项目根目录验证连接：

```bash
cm status --short
```

如果命令能够正常列出本地变更，说明认证、仓库权限和 workspace 均已恢复。

### 不要删除的内容

排查认证问题时，不要删除以下内容：

- 项目根目录中的 `.plastic`
- `~/.plastic4/plastic.workspaces`
- `~/.plastic4/profiles.conf`
- `~/.plastic4/cloudregions.conf`

这些文件保存工作区映射、组织和服务器配置。删除它们不能修复过期令牌，反而可能导致工作区需要重新配置。

### 补充说明

如果日志中只有 `help-actions` 或 `NotificationBarUpdater` 的 HTTP 404，但更新、提交和 `cm status` 均可正常运行，可以暂时忽略。这通常是 PlasticSCM 客户端与 Unity 中国区辅助信息接口之间的兼容问题，不影响核心版本控制操作。
